# Installer artwork and research data retention

`installer.nsi` is adapted from the [Tauri CLI 2.11.4 NSIS template](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.11.4/crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi), copyright Tauri Apps Contributors, under MIT / Apache-2.0. The upstream MIT license is included here.

Changes from upstream: replace the uninstall data-deletion checkbox with an English/Chinese explanation that research data is retained, remove the recursive app-data deletion branch, and adapt upgrade identity/session handling as described below. Keep the upstream resource packaging and WebView2 installation behavior. When upgrading Tauri CLI, review and rebase this template; do not silently return to the data-deleting default. No vault or research directory belongs to the installer.

`hooks.nsh` creates a start-menu uninstall shortcut and removes only a shortcut that still points to this installation. The standard Windows Installed Apps entry and `uninstall.exe` are supplied by NSIS. UI language follows the operating system.

`sidebar.bmp` and `header.bmp` are mechanical layout exports of the original fan-sprite artwork. Regenerate them on Windows with `powershell -NoProfile -File scripts/desktop-brand.ps1`. Regenerate ICO/ICNS with `npx tauri icon assets/brand/fan-sprite-master.png`; copy the generated 512px `src-tauri/icons/icon.png` into `assets/brand/fan-sprite.png` and `desktop-ui/fan-sprite.png`. The larger source covers the launcher's 92 CSS pixels on high-density screens without upscaling a 128px image.

0.2.2 keeps installer registry identity stable across the rename to 扇子 and resolves legacy upgrade paths from the canonical Installed Apps entry. It invokes the verified legacy uninstaller with `/UPDATE /S` and a nonempty `_?=` path after the parent obtains the maintenance choice. `/UPDATE` preserves research data in older uninstallers; `/S` avoids a second confirmation window. Passive upgrades explicitly select uninstall-before-install and skip their uncreated custom dialog. Failure exits 21 (unverified old directory) or 22 (legacy uninstall failed) instead of leaving an unattended message box.

`hooks.nsh` embeds `scripts/desktop-maintenance.ps1` for installer preparation; the uninstaller uses the installed copy before removing program files. The helper checks exact executable paths and current-user ownership. Interactive maintenance asks before closing this installation's desktop and bundled Node processes; silent/passive maintenance returns 10 when they are running, without ending sessions. External Node processes and research files are outside its targets. Review these compatibility changes when rebasing upstream.

`scripts/desktop-installer-check.ps1` only runs on pristine disposable Windows CI runners. It installs the checksum-pinned real 0.2.0 package, removes the historical publisher directory value, exercises busy-runtime refusal, upgrades through the actual legacy uninstaller, then uninstalls/reinstalls. A synthetic vault file must retain its exact hash, and an external Node fixture must survive maintenance. This differs from testing only a fresh installation of the latest version.
