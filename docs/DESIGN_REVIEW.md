# Interface review · 2026-09-05

Scope: the implemented local research workbench, captured in Microsoft Edge at 1600×1050 and 1280×800 with 2× pixel density. All papers and result data in these screenshots are labelled synthetic fixtures. This is a review of working UI, not an image-generated concept.

1. **Start a research conversation — working.** A full-height real CLI remains on the right. The large workspace heading and statistics were removed. Compact controls leave the screen to research content and terminal output. [Startup screenshot](images/empty.png).
2. **Switch research pages — working.** Browser-style tabs support graph, PDF, figures, LaTeX / Markdown writing and notes. Pages can be closed and reopened; the CLI session stays mounted. The paper library and context inspector open as optional drawers. The graph fits the available width and keeps its zoom controls. [Workbench screenshot](images/workbench.png).
3. **Resize and use the terminal — interaction checks passed.** Moving the vertical divider changes width while the canvas keeps its full height; this is asserted in the browser test. Terminal theme, split, maximize, collapse, input and exit checks pass. The cursor remains steady while focused. Closing the browser page still ends its embedded sessions. [Terminal screenshot](images/terminal.png).
4. **Read PDFs, inspect figures and edit manuscripts — working.** Managed files now load from the production-style hidden data directory. A simulated 404 shows a concise message without credentials and can be retried; actual PDF text selection is verified afterward. Existing drafts stay available when changing research tabs. [Reader](images/reader.png), [figures](images/figures.png), [writing](images/writing.png).

Layout reference: [Prism's official workspace introduction](https://openai.com/prism/) and [a public reproduction of its editor screenshot](https://www.how2shout.com/news/openai-prism-gpt-5-2-scientific-writing-workspace.html). The official page's editor image could not be captured directly in this environment; the public screenshot was downloaded and inspected. The adapted principles are compact tabs, adjacent working panes and a large document surface. Paperweave retains the user's real CLI entry and extends the left workspace beyond LaTeX; this is not a claim of complete Prism feature parity.

Evidence limits: screenshots do not establish complete accessibility compliance or subjective visual preference. Automated browser checks use a real Shell and do not validate model response quality, account login or every CLI theme. Fullscreen reader and large-scale graph performance remain separate evaluation tasks. See [validation details](VALIDATION.md).
